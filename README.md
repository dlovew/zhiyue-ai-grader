# 智阅批改助手

一款运行在 **智学网阅卷页面** 上的油猴用户脚本。它读取试卷上的作答图片，结合你配置的参考答案与评分标准，调用 **OpenAI 兼容的多模态大模型（VLM）** 直接评分，并可将分数回填、提交，支持连续批阅、手动改分、历史记录与导出。

- 版本：`1.0.2`
- 适用站点：`www.zhixue.com`、`zhixue.com` 及任意 `*.zhixue.com` 子域
- 脚本类型：Tampermonkey / Violentmonkey 用户脚本（单文件，无需后端）

## 功能特性

- **多模态直评**：只走一条链路——把作答图直接交给视觉语言模型评分，不依赖 OCR 或文本推理。
- **评分标准生成器**：覆盖语文、数学、英语、物理、化学、生物、历史、政治、地理九大学科，按题型生成结构化评分标准；支持文字或图片输入，可手动设置满分，一键填入题目、参考答案与评分标准。
  - 按点给分题（如地理综合题、材料分析题）：只列得分点，答不到不扣分，不生成倒扣/负分规则。
  - 作文、论述题：按档次给分，给出各档分数区间与可观察特征。
- **多平台兼容**：内置 DeepSeek、硅基流动、Kimi、通义千问、智谱、火山方舟等预设，也支持任意自定义 OpenAI 兼容接口；所有请求统一使用 Chat Completions。
- **按平台记忆**：API Key 与模型按平台分别保存，切换平台时自动恢复，不会串号。
- **模型列表获取**：可从接口的 `/models` 端点拉取可用模型并直接选用；平台不支持在线获取时只提示手动填写模型名称。
- **思考模式可切换**：下拉菜单支持「关闭 / low / high / max / 不干预」；关闭模式省 Token，智谱 glm-5 等始终思考的模型改用 low/high/max；一键测试当前模式是否生效。
- **手动改分**：批改结果的总分与每小题分数可直接编辑，提交时使用改后分数。
- **免确认提交**：勾选「一次提交（免确认）」后，手动提交不再弹出二次确认。
- **连续批阅**：自动批改并提交当前试卷，等待换卷后继续下一份，出错或等不到换卷自动停止。
- **历史与导出**：记录每次批改结果，可导出为 CSV 或 HTML。
- **本地缓存与限流**：相同题目与图片命中缓存（默认保留 2000 条，可配），批量合并写盘；支持并发数、RPM、TPM 预算控制。
- **省 Token**：输出三档可调（简略/标准/详细，直接影响输出费用）、紧凑 JSON 协议、`max_tokens` 上限；图片可裁白边、可切块重排（均默认关闭）、精度可选，选了学科后按学科自动套用长边上限。
- **用量可见**：每份结果显示输入/前缀命中/输出 token，高级页累计统计命中率；数据取自响应 `usage`，不额外消耗 token。
- **思考强度随平台**：下拉选项按平台文档变化（DeepSeek 为 none/low/high/max，商汤日日新为 minimal 至 max），默认关闭思考。

## 安装

1. 在浏览器安装油猴脚本管理器（Tampermonkey 或 Violentmonkey）。
2. 获取脚本文件：
   - 从本仓库 `dist/智阅批改助手.user.js` 下载，或
   - 用源码自行构建（见「开发」）。
3. 将 `智阅批改助手.user.js` 拖入浏览器窗口，或在脚本管理器中选择「添加脚本」并粘贴文件内容，确认安装。
4. 打开智学网阅卷页面，脚本会自动挂载一个可折叠的面板；也可通过油猴菜单打开面板、设置、历史等。

> 若脚本管理器要求跨域权限，请放行 `@connect *`，否则无法调用你配置的大模型接口。

## 快速开始

1. 打开智学网阅卷页面，等待面板提示「已读取题号 xx」。
2. 点击面板中的 **设置**，完成以下必填项：
   - **批改上下文**：填写参考答案、评分标准、本方案满分；题目可留空但会影响精准度，建议填写，或用「评分标准生成」一键填入。
   - **接口与链路**：选择平台，填写 API Key 与模型名；点击「测试多模态」验证连通性。
3. 保存配置，返回面板。
4. 点击 **开始批改**，等待结果与分数回填。
5. 如需修正，直接在结果面板中编辑分数，再点击 **提交结果**。

## 使用说明

### 面板按钮

| 按钮 | 作用 |
| --- | --- |
| **开始批改** | 对当前题目读取作答图并调用模型评分，结果写入历史。 |
| **连续批阅** | 循环执行「批改 → 提交 → 等待换卷」；开始前会二次确认，运行中再次点击可停止。 |
| **提交结果** | 把分数填入智学网打分框并提交。默认弹出确认框；勾选旁边的「一次提交（免确认）」后跳过确认。 |
| **历史** | 查看过往批改记录，支持导出 CSV / HTML 与清空历史。 |
| **设置** | 打开配置面板。 |

### 设置面板

设置面板分为四个标签页：

1. **批改上下文**
   - 题目、参考答案、评分标准、满分。
   - 参考答案与评分标准为必填；满分需大于 0，且应与试卷实际分值一致。
   - 提示：题目留空时模型只能依据作答图与参考答案推断，批改精准度会下降。

2. **接口与链路**
   - 平台预设下拉框：仅内置平台；其他平台选「自定义（手动填写）」。切换平台会自动恢复该平台此前填写的 API Key、模型与思考模式，但**不会自动填入默认模型**，模型名需自行填写或从模型列表选择。
   - 接口地址、API Key、模型名：均可手动修改；点击「获取模型列表」可拉取接口支持的模型并选用。
   - **思考模式**（下拉菜单）：
     - `关闭`：注入关闭字段，省 Token、更快，适用于允许关闭思考的模型（字段名随平台不同）。
     - `low / high / max`：注入思考强度，用于**始终思考、不支持关闭**的模型（如智谱 `glm-5.3-flash`）。按智谱官方格式发送 `thinking: {"type":"enabled"}` 加独立的 `reasoning_effort: "low"`（或 `high` / `max`），强度字段直接控制推理深度。选关闭会对这类模型报 HTTP 400「该模型始终思考，不支持关闭思考；请使用 low、high 或 max」。
     - `不干预`：不发送任何思考参数，使用模型默认设置。
     - 思考模式会**随平台自动切换**：每个平台单独记忆自己上次的选择（与 API Key、模型一样），切换平台时自动恢复。
     - 点击「测试当前思考模式是否生效」可验证；关闭模式检测响应中的推理字段与推理 token，强度模式确认参数被服务端接受。测试使用独立的 60 秒超时、不占用批改限流预算，并实时显示已用秒数；长链推理模型可能需要数十秒，请耐心等待。
   - 「测试多模态」：发送一条最小请求验证接口可用。

3. **评分标准生成**
   - 选择学科与题型，填写满分（手动输入），输入题目与标准答案（文字或上传图片）。
   - 点击「生成评分标准」，结果在线可编辑，化学式、公式等符号可直接粘贴。
   - 点击「一键填入题目、参考答案、评分标准」会同时写入批改上下文的题目、参考答案、评分标准与满分。

4. **高级**
   - 导出 / 导入配置：备份或恢复配置、各平台 Key、模型与思考模式。
   - 重置默认、清空数据。

### 手动改分

批改完成后，结果区里的总分与各小题分数都是可编辑的数字框：

- 修改某个小题分数后，总分会自动按各小题求和更新。
- 直接修改总分时，各小题分数会按比例调整并做尾差修正。
- 提交时始终使用当前显示的（改后）分数，且不会污染缓存中的原始批改结果。

### 连续批阅

点击「连续批阅」并确认后，脚本会：

1. 批改当前试卷；
2. 静默提交分数；
3. 等待阅卷列表切换到下一份（通过作答图片标识判断）；
4. 自动继续，直到点击停止、出现错误或超时未换卷。

**关于切换界面**：提交后等待换卷期间，你可以切换到其它标签页、最小化窗口或让页面处于后台，连续批阅不会因此中断——后台等待会暂停超时倒计时，且换卷识别不依赖图片是否加载完成。请注意保持阅卷标签页处于打开状态且停留在阅卷页面；若导航离开该页面导致脚本被重新加载，连续批阅状态将丢失，需重新开启。

连续批阅跳过所有确认弹窗，请确认评分标准准确后再开启。

### 历史与导出

- 历史记录包含：时间、题号、链路、模型、状态、得分/满分、小题分、评分依据、是否需复核、是否已提交。
- 可导出为带 BOM 的 CSV（Excel 可直接打开）或独立 HTML 文件。
- 历史条数默认上限 500，可在配置中调整。

## 支持的服务平台

内置预设包含：`自定义`、`opencode.ai`、`DeepSeek`、`商汤日日新（SenseNova）`、`硅基流动`、`Kimi / Moonshot`、`通义千问 / DashScope`、`智谱 GLM`、`火山方舟（Chat）`。

**思考强度随平台变化**，下拉只列出该平台文档支持的档位（默认「关闭思考」）：

| 平台 | 可选档位 | 传参方式 |
|---|---|---|
| DeepSeek | 关闭 / 模型默认 / low / high / max | `reasoning_effort` = none / low / high / max；「模型默认」不传 |
| 商汤日日新 | 模型默认 / minimal / low / medium / high / xhigh / max | 直接发 `reasoning_effort`；官方未提供关闭字段，选「模型默认」即不传 |
| 硅基流动 | 关闭 / 模型默认 / high / max | 关闭发 `enable_thinking=false`；强度发 `reasoning_effort` |
| 智谱 GLM | 模型默认 / low / high / max | `thinking.type=enabled` + `reasoning_effort`；glm-5 类模型无法关闭思考 |
| 通义千问 | 关闭 / 模型默认 | 关闭发 `enable_thinking=false` |
| Kimi / 火山方舟 | 关闭 / 模型默认 | 关闭发 `thinking.type=disabled` |
| 自定义 | 关闭 / 模型默认 | 不注入任何参数，靠模型自身默认 |

商汤日日新按官方示例预填：推理 `POST https://token.sensenova.cn/v1/chat/completions`，模型列表 `GET https://token.sensenova.cn/v1/models`（Bearer 鉴权，模型默认 `sensenova-6.8-flash`）。点「获取模型列表」即可拉取，返回里 `input_modalities` 含 `image` 的视觉模型会自动排在最前；思考强度直接通过顶层 `reasoning_effort` 传递。

硅基流动使用说明：`enable_thinking` 只接受布尔值，所以「关闭」模式发送 `enable_thinking: false`；强度改用顶层 `reasoning_effort`（按官方文档 `low`/`medium` 由服务端映射为 `high`，`max` 原样发送）。选「模型默认」时不发送任何思考参数，但部分模型默认开启思考并生成长链推理，72B 等大模型处理图片时可能超过默认 120 秒超时——可在「高级」里调大请求超时，或换用更小的视觉模型，或选「关闭」模式关闭思考。

选择平台仅填充建议的接口地址、模型与协议参数，**你填写的 endpoint / model / apiKey 始终优先**。需要注意的是：

- 必须使用支持图片输入的多模态模型（如 `gpt-4o`、`qwen-vl-max`、`glm-4v-flash`、`doubao-seed` 系列等）。
- 接口需兼容 OpenAI Chat Completions 协议（`POST /chat/completions`）。
- API Key 仅保存在浏览器本地（通过 `GM_setValue`），不会上传到任何第三方服务器。

## 成本与缓存

**本地结果缓存**

- 命中条件：题目、参考答案、评分标准、满分、小题、作答图（URL 列表）、模型、图片处理参数、思考模式全部一致。
- 默认 2000 条、30 天有效；双评大卷建议把「缓存条数上限」提到 3000。
- 写入为合并批量（约 1.2 秒一次，页面关闭前补写），超限按 10% 分批淘汰，不会整表清空；存储配额满时提示一次并停止写入。
- 命中后不再发送请求，输入与输出 token 都省掉；缓存里不保存模型原文，只留评分结果。

**图片 token**（只受像素尺寸与精度影响，JPEG 质量不影响计费）

- 自动剔除重复图、空白图与废图（不收 token）。
- 可选「裁切空白边距」：默认关闭，开启后保留 6% 边距保护边缘作答。
- 可选「宽扁作答条切块重排」：默认关闭。仅当宽高比大于 3.2 且高度不小于 200px 才生效，把长条切成等宽小块铺成近方形，tile 数可降到约 1/3；**并排小空的填空题不要开启**，切块会打乱空的对应关系。
- 精度可选 `high` / `auto` / `low`：`low` 仅适合选择、填空判对错；主观题请用 `high`。使用低精度，或原图清晰但被缩到短边小于 320px 时，结果会自动标记人工复核。
- 学科策略：在「批改上下文」选定学科后自动套用长边上限——数学/物理/化学 1600px，语文/英语/生物 1440px，历史/政治/地理 1280px，精度一律 `high`；关闭「按学科自动套用」则完全按手动参数。未选学科时不生效。
- 多图合并：默认关闭。开启后同题两张图纵向拼成一张，省掉每张图的固定开销（约 28%）；仅当两图短边都 ≥ 1100px 且拼后不过高时生效，会略微降低单页有效分辨率，公式密集的题目不建议开。

**输出 token**

- 输出一律使用紧凑协议：`s` 状态（单字母）、`sc` 得分、`c` 置信度、`r` 评语、`sub` 数组用 `i` 索引代替小题名称；满分与「满分小题的扣分理由」不再由模型回写。
- **输出档位三档**（「高级」里切换，直接决定输出 token）：
  - 简略：只打分与置信度，不写任何理由，`max_tokens` 400，最省；
  - 标准：总评语 ≤ 30 字 + 仅扣分小题给 ≤ 20 字理由，`max_tokens` 800；
  - 详细：总评语 ≤ 60 字 + 每题 ≤ 40 字依据，`max_tokens` 1400，最贵但便于复核。
- 开启思考时，上述上限会按 1.8 倍放宽，避免推理内容挤占导致 JSON 被截断。
- 输出档位与思考档位都会进入缓存键，切换后不会误命中旧结果。

**用量可见**

- 每份结果下方直接显示：`输入 1234（前缀命中 900）· 输出 180（含思考 60）`，数据来自响应自带的 `usage`，**读取它不产生任何额外 token，也不额外发请求**。
- 本地缓存命中时显示「缓存命中」，该次零 token 消耗。
- 「高级」页底部显示累计统计：批改次数、本地命中次数与命中率、请求次数、累计输入/前缀命中/输出 token。全部为本地计数，可在「清空数据」时一并清除。

## 开发

项目为模块化源码，构建脚本按固定顺序把 `src/` 下的片段拼成单文件用户脚本，零第三方依赖。

```bash
# 构建
node build.mjs

# 运行测试
node tests/api-compat.test.mjs
```

- `src/`：功能源码（适配器、基础设施、核心流程、UI）。
- `build.mjs`：拼接与横幅生成。
- `dist/智阅批改助手.user.js`：可直接安装的产物。
- `tests/`：接线与行为一致性测试。

修改源码后需重新执行 `node build.mjs` 才会更新 `dist/` 中的脚本。

## 注意事项

- 请先在少量试卷上验证评分标准与模型效果，再用于大批量阅卷。
- 不同模型的打分尺度差异较大，建议固定一个模型并配套调整评分标准。
- 「思考模式」是否生效取决于服务端实现，可用内置测试按钮验证；智谱 glm-5 等始终思考的模型请用 low/high/max，不要用「关闭」。
- 连续批阅会自动提交分数，请谨慎开启。
